4. THINGS THE HUMAN SHOULD LOOK AT BEFORE PART 4
================================================================================

4a. ONE OBSERVATION THAT DOES NOT MATCH A PREREG SENTENCE (reported, not acted
    on). Section 3 says the commit rule "is robust to tightening the rank
    threshold to 2". On this data that holds for the J-lens (rank<=2 layers are
    still 9,10,11 -> commit L9-11 unchanged) but NOT for the R-lens: at rank<=2
    the R-lens has only L8 (rank 2) and L9 (rank 1), a run of 2, which is below
    the 3-layer minimum, so the R-lens commit would disappear entirely. The
    R-lens streak is carried at rank exactly 3 at L10 and L11.
    I have changed NOTHING: the frozen threshold is rank<=3 and that is what
    ran. Flagging it because the robustness sentence in the prereg is stronger
    than the data supports, which may matter for the write-up.

4b. UNDERSPECIFICATIONS I HAD TO RESOLVE. Full reasoning is in
    results/confirmatory_01-09/research_log.md. Each needs your sign-off:
    - Italy's surface-form list is not tabulated in the prereg (boot is the
      control). I applied section 3's general rule to get
      {Italy, Italian, Italia, 意大利}, the same shape the table uses for
      Brazil and Mexico. This affects the control and this validation only.
    - FP-P is defined per commit but precision is per claim. Resolution: on a
      twin, if the lens commits to country X then every in-band claim of X on
      that twin is FP-P; non-committed country claims stay UNSCORED (they are
      the smear the twin should produce). On a forced-choice twin the FP-P
      bucket only opens if exactly ONE country was committed to.
    - The bare condition has no FP definition in the prereg. Scored
      structurally like a twin, reported descriptively, never pooled.
    NOTE: none of these three was exercised by this validation -- the pilot
    twin and bare runs produced no country tokens at all, so the FP-P path has
    NOT been tested against known-good data. It will first do real work in
    Part 4. Its logic is stated above so you can check it by reading.

4c. THE REGISTRY. Full audit in registry_tokens.txt. 52 tokens over 6
    countries. Two properties worth your eye:
    - Suriname has NO single-token Latin form ('Sur'+'iname'), so it is
      registered only through first-token forms. Without the prereg's
      first-token rule the dutchSA item would silently score nothing.
    - The flagged first-token registrations that survive the fragment filter
      are ' BRA' 'BRA' ' CAN' 'CAN' ' ITAL' 'ITAL' ' SUR' 'SUR' ' Sur' 'Sur'
      ' sur' ' mex' 'Mex'. ' sur' and 'Mex' are ordinary strings and could
      false-match. Mitigation, reported not tuned: every claim row carries
      form_kind, and summary.json reports an exact-forms-only sensitivity
      analysis beside every headline number.
    - Ambiguous single-character shards were NOT registered ('K' from 'Korea',
      'm' from 'mexico', the bare SPACE token from ' 意大利', '加', '苏').
      Registering those would have fired spurious commits everywhere.

4d. WHAT THIS VALIDATION COULD NOT TEST, because the pilot data does not
    contain it:
    - k=25 secondary scoring. The pilot files hold top-10 only, so only the
      k=10 path is exercised. The k=25 path is the same code with a different
      constant; Part 4 files will carry top-25.
    - Mouth-exclusion tags (top-1 / top-5 of the model's own next token). Run 1
      does not record the model's next-token distribution at the entity
      position, so mouth_top1/mouth_top5 are NA on every row here. Part 4 will
      record the model's top-25 next token at every position, and the tags will
      populate. UNTESTED CODE PATH.
    - Bootstrap CIs. The bootstrap resamples ITEMS, and this validation has one
      item (boot). A CI over one item is meaningless, so the scorer returns the
      point estimate with null bounds. With 5 confirmatory items it will run
      properly. LARGELY UNTESTED CODE PATH.
    - FP-C. No cross-item country token ever appeared, so the FP-C branch never
      fired. UNTESTED CODE PATH.
